# wye-map

프로젝트 자료를 읽어 **원문 근거가 연결된 지식 맵**을 만들고, 이를 바탕으로 문제를 구조적으로 분석하는 Claude Code · Codex 스킬입니다.

회의록, 사업계획서, 제안서, 요구사항 정의서, 주간·월간 보고서가 쌓인 폴더를 지정하면 목표·문제·현행 업무·데이터·요구사항 간의 관계를 정리합니다. 이어서 문서 간 불일치와 확인이 필요한 항목을 찾아 공유용 요약과 확인 질문지로 정리합니다. 별도 서버나 계정 없이 로컬 PC에서 동작합니다.

## 주요 기능

- **근거 기반 지식 맵**: 모든 항목과 판단에 원문 인용을 연결합니다. 인용은 원문과 글자 단위로 대조하므로, 자료에 없는 내용은 검사 단계에서 걸러집니다.
- **문제 정의 구조 분석**: 문제마다 `현상 → 지표 → 현행 판단 방식 → 판단 근거 데이터 → 요구사항 → 목표`의 연결을 점검하고, 비어 있는 항목을 확인 질문으로 정리합니다.
- **문서 간 정합성 점검**: 같은 대상에 대해 문서마다 다르게 기재된 수치·범위·대상(예: 대상 인원 380명과 450명)을 찾아 근거와 함께 제시합니다.
- **해결 방향 판정**: 문제별로 접근 방식(절차 개선, 시스템 도입, 데이터 분석 등)과 실행 가능성(가능 / 조건부 가능 / 현재 불가)을 판정하고 선행 조건을 정리합니다.
- **자료 자동 선별**: 이전 버전, 동일 문서의 중복본(PDF·Office), 행정 서류는 제외 사유와 함께 걸러 내고 핵심 문서만 분석합니다.
- **업종·언어 대응**: 업종 공통 프로필이 기본이며, 제조 AI 컨설팅 프로필을 함께 제공합니다. 한국어·영어 자료를 모두 처리합니다.

## 산출물

분석 결과는 작업 폴더의 `Wye/`에 생성됩니다.

| 파일 | 내용 |
|---|---|
| `맵.html` | 오프라인으로 열리는 대화형 화면. 문제 구조 보드, 계층별 연결도, 전체 관계도, 항목 목록, 정합성 점검 결과를 제공합니다. |
| `요약.md` | 공유용 진단 요약. 핵심 문제와 판정, 문서 간 불일치, 담당자별 확인 사항을 한 문서로 정리합니다. |
| `질문지.xlsx` | 담당자별 확인 질문지. 답변·담당·기한 칸을 채워 자료 폴더에 넣으면 다음 분석에 근거로 반영됩니다. |
| `분석/<문제명>.md` | 문제별 분석서. 문제 정의 구조, 가설과 반대 근거, 판정과 선행 조건, 영향 범위를 담습니다. |
| `위키/` | 계층별 항목 설명과 근거를 정리한 문서 묶음 |

## 요구 환경

| 항목 | 내용 |
|---|---|
| 에이전트 | Claude Code 또는 Codex CLI |
| 운영체제 | macOS, Windows, Linux |
| Python | 3.9 이상 (표준 라이브러리만 사용) |
| 문서 변환 | [markitdown](https://github.com/microsoft/markitdown) — PDF·Word·PowerPoint·Excel 처리에 필요 |
| 선택 | `pdftotext`(poppler) — 50MB를 넘는 PDF 처리, Google Drive for Desktop — Drive 링크로 자료 지정(macOS) |

## 설치

**macOS · Linux**

```sh
git clone https://github.com/deephoon/wye-map.git ~/dev/wye-map
~/dev/wye-map/install.sh
pipx install 'markitdown[pdf,docx,pptx,xlsx]'
```

**Windows (PowerShell)**

```powershell
git clone https://github.com/deephoon/wye-map.git $HOME\dev\wye-map
& $HOME\dev\wye-map\install.ps1
pipx install "markitdown[pdf,docx,pptx,xlsx]"
```

설치 스크립트는 스킬을 `~/.claude/skills`와 `~/.codex/skills`에 등록한 뒤 환경 점검 결과를 보여 줍니다. 점검은 언제든 다시 실행할 수 있습니다.

```sh
python3 ~/dev/wye-map/_core/scripts/doctor.py
```

## 사용 방법

분석 결과를 저장할 빈 폴더를 만들고, 그 폴더에서 에이전트를 실행합니다.

```sh
mkdir -p ~/Wye/my-project && cd ~/Wye/my-project
claude
```

자료 폴더 경로나 Google Drive 링크와 함께 요청합니다.

```text
/wye-map ~/Documents/프로젝트자료 이 폴더 자료로 맵을 만들고 핵심 문제를 분석해 줘
```

이후에는 일반적인 문장으로 이어서 요청할 수 있습니다.

- "데이터 수집 지연 문제를 분석해 줘"
- "이 요구사항이 바뀌면 영향받는 항목을 정리해 줘"
- "자료가 추가됐으니 다시 읽어 줘" — 변경된 파일만 다시 처리합니다.

Codex에서는 `$wye-map ~/Documents/프로젝트자료 …`처럼 스킬 이름을 앞에 붙여 호출합니다.

## 처리 흐름

| 단계 | 내용 | 담당 |
|---|---|---|
| 1. 자료 선별 | 이전 버전·중복본·행정 서류를 제외하고 핵심 문서를 고릅니다. 파일이 많으면 선별 결과를 보여 주고 확인을 받습니다. | 스크립트 |
| 2. 변환·분할 | 문서를 텍스트로 변환하고 인용 가능한 단위로 나눕니다. 변경된 파일만 다시 처리합니다. | 스크립트 |
| 3. 맵 작성 | 자료를 읽고 항목·관계·근거·문서 간 불일치를 작성합니다. 분량이 많으면 색인을 따라 핵심 부분부터 읽습니다. | 에이전트 |
| 4. 검사 | 인용 대조, 허용된 관계 유형, 항목 수 상한, 불일치 근거를 검사합니다. 오류가 있으면 수정 후 재검사합니다. | 스크립트 |
| 5. 분석 | 문제별 분석서를 작성하고, 인용과 판정 규칙의 정합성을 다시 검사합니다. | 에이전트 · 스크립트 |
| 6. 산출물 생성 | 화면, 요약, 질문지, 위키를 생성합니다. | 스크립트 |

인용 대조, 문제 구조 계산, 판정 규칙 검사는 정해진 규칙으로 수행하므로 같은 맵에서는 항상 같은 결과가 나옵니다. 판정 자체는 에이전트가 작성하고, 규칙에 어긋나면 검사에서 걸러집니다.

## 프로젝트별 설정

처음 실행할 때 에이전트가 자료를 보고 프로필을 선택하고, 선택 결과를 알려 줍니다.

| 프로필 | 대상 | 특징 |
|---|---|---|
| `general` (기본) | IT 구축, 서비스 기획, 일반 컨설팅·PM | 판정 항목명 "해결 방향 판정", 업종 공통 용어 |
| `manufacturing-ai` | 제조 AI · 스마트공장 | 설비·공정 용어, 호기·㎛·℃ 등 단위, "AI 적용 판정"과 학습 데이터(라벨) 규칙 |

문서 명명 규칙, 제외할 서류, 단위, 결과 언어는 작업 폴더의 `.wye/config.json`에서 조정합니다.

```json
{
  "profile": "general",
  "language": "en",
  "triage": { "core": ["SRS", "화면설계"], "admin": ["견적"] },
  "units": ["TPS", "ms"]
}
```

설정 항목 전체는 [`_core/docs/profiles.md`](_core/docs/profiles.md)를 참고하십시오.

## 데이터 보안

- 원본 자료 폴더에는 어떤 파일도 생성하거나 수정하지 않습니다.
- 모든 처리는 로컬에서 이루어지며, 자료를 외부 서비스로 전송하는 별도 기능은 없습니다. 단, 맵 작성 과정에서 에이전트(Claude, Codex)가 자료 내용을 읽습니다.
- `Wye/`와 `.wye/`에는 원문 일부가 포함됩니다. 공개 저장소나 외부 공유 공간에 올리지 마십시오.

## 저장소 구성

```text
wye-map/            설치되는 스킬 (SKILL.md, 절차 문서, 스크립트 복사본)
_core/
  scripts/          변환·검사·분석·화면 생성 스크립트 (원본)
  data/             온톨로지, 업종 프로필
  docs/             맵 작성 규칙, 자료 지정, 프로필 문서
  viewer/           맵 화면 템플릿
  tests/            단위 시험
install.sh          macOS · Linux 설치
install.ps1         Windows 설치
sync_core.py        _core를 스킬 폴더로 복사
```

## 개발

공용 코드와 문서의 원본은 `_core/`입니다. 수정한 뒤에는 스킬 폴더에 반영하고 시험을 실행합니다.

```sh
python3 sync_core.py
python3 -m unittest discover -s _core/tests
```

`_core`와 스킬 폴더의 복사본이 다르면 시험이 실패합니다.
