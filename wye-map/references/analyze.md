# 맵으로 분석

맵(`.wye/map.json`)이 검사를 통과한 뒤에 한다. 없으면 `SKILL/shared/map.md`로 먼저 만든다.

## 순서
0. `python3 SKILL/scripts/profiles.py .wye` — 판정 이름(`verdictTitle`)과 접근 목록(`approaches`)을 확인한다. 아래 양식의 그 두 곳은 프로필 값을 쓴다
   (범용: "해결 방향 판정" · 절차 개선/시스템·전산화/데이터 분석/외부 도입/범위 밖, 제조 AI: "AI 적용 판정" · 절차 개선/규칙/통계/ML/DX).
   결과 언어(`language`)가 `en`이면 분석 한 장을 영어로 쓴다(인용은 원문 그대로): 폴더 `Wye/Analysis/`, 표시어 `- **Verdict**:`(Feasible /
   Conditionally feasible / Not feasible now), `- **Conditions**:`, `- **Next checks**:`(줄마다 "<Owner> should …" 또는 "<Owner>: …"). 요약·질문지는 `Summary.md`·`Questions.xlsx`.
1. `python3 SKILL/scripts/check.py .wye` → `python3 SKILL/scripts/analyze.py .wye` (영향 범위가 궁금하면 `--impact "<항목 이름>"`).
   출력: 문제마다 고리 자리별 개수와 빈 자리, 구조(고립·한 줄 매달림·중심), 영향 범위.
2. 사람이 고른 문제(안 골랐으면 중심에 가까운 문제부터, 셋까지)마다 **분석 한 장**을 `Wye/분석/<문제 이름>.md`에 쓴다(양식 아래).
   - 고리 표의 칸은 `analyze.py` 결과 그대로. 빈 자리는 빈 채로 두고 "확인할 것"으로 넘긴다.
   - 문장마다 근거: `확인` = 맵 항목의 원문 인용(`.wye/text/`에서 다시 읽어 옮김), `추론` = 어떤 항목·관계에서, `미확인` = 누구에게 물을지.
   - 원문 인용은 큰따옴표 `"…"` 안에 글자 그대로, 바로 뒤에 `[D001]`(문서 id만, 조각 번호를 알면 `[D001-S0003]`)을 붙인다.
     따옴표는 원문 인용에만 쓴다(말 예시는 「」). 제목(`# `)은 맵의 문제 이름과 같게.
   - `- **다음 확인**:` 아래는 줄마다 "<물을 곳>은/는 …" 꼴로 쓴다 — `요약.md`·`질문지.xlsx`가 물을 곳별로 묶는다.
3. **정합성 검사**: `python3 SKILL/scripts/verify.py .wye` — 인용이 원문에 있는지, 판단 데이터가 비었거나 필요한 데이터가
   미수령·설치 전인데 판정을 `가능`으로 쓰지 않았는지 본다. 오류를 고쳐 다시(최대 3회), 남으면 보고에 적는다.
   그다음 `python3 SKILL/scripts/render.py .wye`로 화면·`요약.md`·`질문지.xlsx`를 다시 만든다(보드 맨 위 진단 요약에 판정이 뜬다).
4. 보고 (세 줄): 분석한 문제 수와 판정 · 열 파일 · 다음에 할 말(예: "이 문제의 요구사항을 정리해 줘" — wye-requirements가 있으면 그쪽으로).

## 분석 한 장 양식

```markdown
# <문제 이름>

**본질**: <증상이 아니라 실제로 어긋난 것 한 문장> (확인/추론)

## 문제 정의 고리
| 자리 | 맵 항목 | 근거 |
|---|---|---|
| 현상 | … | "원문" [D00X-S00YY] |
| 지표 | … | |
| 현재 판단 | … (빈 자리면 "비어 있음 — 누구에게 무엇을") | |
| 판단에 쓰는 데이터 | … | |
| 요구사항 · 개선에 필요한 데이터 · 목표 | … | |

## 가설과 반대 근거
| 가설 | 지지 근거 | 반대 근거 / 없음 |
|---|---|---|

## <verdictTitle — 예: 해결 방향 판정 / AI 적용 판정>
- **접근**: <approaches 중 하나> — 이유 한 문장
- **판정**: 가능 / 조건부 가능 / 지금은 불가
- **조건**: 자료·기간·담당·결정처럼 무엇이 갖춰지면 되는지
- **없는 데이터**: …
- **다음 확인**: 누가 · 무엇을

## 영향 범위 (바뀌면 흔들리는 것)
- <analyze --impact 결과에서 이 문제와 이어진 항목 상위 몇 개>
```

## 판정 규칙 (모든 프로필)
- **가장 단순한 접근부터.** 기록 누락·담당 불명·기준 부재가 원인이면 접근 = 절차 개선. 시스템·AI는 그다음.
- 판단에 쓰는 데이터 자리가 비었거나, 데이터의 위치·연결 키·건수를 모르면 판정은 "조건부" 이하(`verify.py`가 검사).
- 판정 낱말은 "가능 / 조건부 가능 / 지금은 불가" 셋만 쓴다(화면·요약이 이 낱말로 색을 정함).

### 제조 AI 프로필 추가 규칙
- 예측·탐지·분류인데 정답(라벨) 기록의 출처를 모르면 "조건부", 라벨이 없다고 확인되면 "지금은 불가"(라벨 수집이 먼저).
- 단순 절차 개선으로 풀리면 AI를 권하지 않는다.

### 공통

- 미확인이 남아도 판정은 내린다 — 조건부로, 조건을 적어서. "판단 보류"로 끝내지 않는다.
- 경로가 있다고 인과가 아니다. 원인은 자료가 직접 말할 때만 원인으로 쓴다.
- 수치·이름은 원문 그대로. 일반 지식은 `일반 지식:`으로 따로 표시.
